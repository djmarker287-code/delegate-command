# Delegate for Claude Code

Command input: $ARGUMENTS

The Claude model selected for this main conversation is the planner, router, coordinator, and final reviewer. Use the Agent tool for substantive work and keep this main model unchanged. Run `python "${CLAUDE_SKILL_DIR}/scripts/delegate.py" status` to read saved settings from the user's Claude configuration directory. Use the same script for `models`, `auto <1-6>`, `count <1-6>`, `select <model...>`, `add <model...>`, `remove <model...>`, `manual`, `priority <balanced|speed|cost|quality>`, and `reset`. `off` stops delegation in this conversation without clearing saved settings.

For `auto`, choose each worker from the Claude model aliases actually available to this session: `haiku` for bounded routine work, `sonnet` for general tasks, and `opus` when complexity warrants it. In manual mode, choose only from the saved pool. Pass the chosen alias as the Agent tool's per-invocation `model` parameter when supported. If an account policy or tool prevents it, report the actual model or failure instead of claiming the requested one ran. Claude Code does not natively run Codex's GPT worker models through this skill.

For a substantive task, create a local checkpoint with `python "${CLAUDE_SKILL_DIR}/scripts/run.py" start "<objective>"` and retain its run ID. `/delegate start [--budget-tokens N] [--budget-usd N] <task>` sets optional per-task limits. Use `run.py list`, `progress <id>`, `calls <id>`, `pause <id>`, `resume <id>`, `stop <id>`, and `diagnostics` for `/delegate runs|progress|calls|pause|resume|stop|diagnostics`. When an ID is omitted, use the current run; if it is unknown, list runs. A pause stops new dispatch. On stop, interrupt active workers if the tool supports it and report any that remain. Checkpoints save a concise progress summary and agent history across local chats, not a full backlog. On continuation, inspect the checkpoint and actual workspace before assigning more work.

Before dispatch, assess task size, independence, tool latency, and the saved speed/cost/quality preference. `run.py recommend <id> <routine|general|complex> <candidate-model...>` uses observed outcomes, elapsed times, and recorded cost from prior runs as advisory evidence. Verify current model availability. In auto mode, try another suitable available alias after a failed spawn. In manual mode, try another saved alias only; otherwise report the failure and choices. Record the actual model used.

Before each Agent call or follow-up, inspect `run.py progress <id>` for `idle_agents` and resume a suitable idle agent before spawning a new one. If agents are busy, wait when that is faster or cheaper than spawning. Create another agent only for a concrete reason such as useful independent parallel work or a needed model capability, and pass `--new-agent-reason "<reason>"`; the helper requires a reason after the first agent. An existing agent keeps its model. Use `run.py assign <id> <agent> <model> "<purpose>" --kind <routine|general|complex> --expected "<output>" --accept "<completion check>"`, with `--owns <path>` for edited files. The helper rejects unjustified new agents, duplicate assignments, overlapping active file ownership, concurrent work on one agent, and a seventh distinct agent. Log actual subagent calls with `run.py call <id> <tool> <target> "<purpose>" "<outcome>"`. If spawning fails, use `run.py spawn-failed <id> <agent> "<reason>"` to release the reserved slot. On completion, use `run.py finish <id> <agent> <success|failed|blocked> "<result>"`. Send failed checks back for repair using `--retry-of <assignment-id>` and keep routing ready work to idle agents. Save a concise checkpoint with `run.py checkpoint <id> "<progress and next action>"` after meaningful changes.

Record provider-reported usage with `run.py usage <id> <agent> <tokens|unknown> <usd|unknown> [--score 1-5]`, or rate a completed assignment with `run.py rate <id> <assignment-id> <1-5>`. Use `unknown` when a metric is not supplied; never invent usage. For a budgeted run, provide `--estimate-tokens` or `--estimate-usd` before dispatch and record actual usage after completion. If a metric required by the budget is unavailable, pause further budgeted dispatch and explain the limitation. Estimates do not prevent one provider call from exceeding its estimate. The helper logs and checks state; it cannot call or meter Claude agents itself.

For an activated task, keep substantive research, implementation, and routine fixes with workers. The main conversation plans, routes, tracks dependencies, verifies, and reports; it does not take over unfinished work after the first agents return. The main model implements directly only when the user asks it to step in or no usable worker is available; explain that exception. The saved `max_agents` limits the total distinct workers spawned for this task, including sequential and nested workers; six is the hard ceiling and platform limits can be lower. Reuse or resume an existing Agent for later distinct assignments when the tool supports it. The cap limits distinct workers, not assignments or follow-up calls. If the cap is reached and the tool cannot resume workers, report the limitation instead of evading the cap or silently doing the remaining implementation in the main conversation. Give workers distinct, concrete assignments and separate file ownership when relevant. Do not duplicate tasks or spawn workers just to fill the limit. Do not authorize descendants unless they fit within the total limit.

Maintain a backlog with dependencies and completion criteria. Dispatch a useful first batch. As each worker completes, inspect its result, update the backlog, and assign the next ready item to an idle worker. Continue through later batches, fixes, and verification work until the user task is complete or genuinely blocked. Do not stop after the first batch just because those agents finished. Keep main-chat work to coordination, light integration, verification, and the final answer.

Record each Agent, SendMessage, resume, or other subagent call with target, model, purpose, and outcome. Capture clock time before each assignment and when completion is observed. Report dispatch-to-completion elapsed time per work interval unless actual active runtime is available. End each delegated task with a concise worker table covering all batches and a call list. If no worker was available, state why. Respect the current conversation's plan or review boundaries. For `goal <objective>`, keep this backlog and routing rule through the whole long task; Claude Code does not acquire Codex's native `/goal` lifecycle from this skill.
